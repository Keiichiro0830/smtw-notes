# 提出BOX・コメントのバックエンド（GAS）が止まったとき

ポータルのコメント・ファイル提出BOX・配布BOX は、Google Apps Script の Web アプリ（プロジェクト「知的鍛錬塾コメント」、所有者の Google アカウントで実行）が受けている。コードの原本は `_src/gas_comment_backend.gs`（ID を含むので git には入れない）。

## 見分け方

- Web アプリの URL に `?ping=1` を付けて開くと、正常なら `{"ok":true,"upload":true,...,"version":N}` が返る。
- ログインしていない状態で開くと 403「アクセスが拒否されました」が返り、所有者のアカウントで開くと「Authorization needed」と出る場合は、承認が外れている。
- GitHub Actions の「GAS health」が毎日 07:00 JST に同じ確認をし、失敗すると issue を立てる。
- GAS 側でも `healthCheck` を毎日トリガーで動かしているので、承認が外れると Google からトリガー失敗のメールが所有者に届く。

## 承認が外れる主な原因

- 所有者の Google アカウントのパスワードを変えた（Gmail 系の権限を持つトークンが取り消される）。
- コードに新しいサービスを足して、必要な権限が増えた（再承認するまで止まる）。
- Google アカウントの「サードパーティのアプリとサービス」（セキュリティ診断を含む）で、このアプリを削除した。名前が「無題のプロジェクト」と出ることがあるが、消さない。

## 復旧（3手順）

1. Apps Script エディタで関数 `doGet` を選んで「実行」→「権限を確認」→ 所有者のアカウントを選ぶ →「詳細」→「（安全ではないページ）に移動」→ 許可。
2. 「デプロイ」→「デプロイを管理」→ 鉛筆 → バージョン「新バージョン」→「デプロイ」。今のデプロイを編集するので URL は変わらず、ポータル側の変更は要らない。
3. `?ping=1` が `ok:true, upload:true` と最新の `version` を返すことを確かめる。GitHub の「GAS health」を手動実行（Run workflow）して緑になれば、立っている issue を閉じる。

## 注意

- コードを直したら、必ず手順2で「新バージョン」を配備する。保存しただけでは本番に反映されない。
- GitHub の定期実行は、リポジトリに60日間コミットが無いと自動で止まる。Actions 画面に止まった旨が出たら、もう一度有効にする。
