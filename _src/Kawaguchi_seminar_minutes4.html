9.1 講義: LLMの本質と4つの活用類型

  • 当日スライドはピッツバーグ大学 Ferrara の NBER 論文（WP 35374・経済史研究における LLM・生成AI 活用の実践ガイド）がベース。専門技能のない研究者でも研究ができるようになったことを実証した論文で、解析エラーが40%から1%未満に低減した例などが紹介された。
  • LLMの本質は「文脈依存の単語予測器」。統計的言語モデル → ニューラルネットワーク → カーネル平滑化（移動平均で周辺情報を取り込み依存関係を持たせる）という流れがトランスフォーマーの仕組みにあたる、と昨年ゼミの時空統計学に接続して解説。1980年代後半の知識工学（If-then-else型エキスパートシステム）との対比も。
  • 誤用の原因は擬人化（「知能」「人間」と見なすこと）。「単語予測器に過ぎない」と割り切ることで使い勝手が飛躍的に上がる。
  • 4つの活用類型: ①チャットウィンドウ（最も普及）②IDE統合型アシスタント（RStudio等に組み込み）③エージェンティック（Claude Code のようにファイル読み書き・実行まで自動化、研究助手として使える）④APIモデル（研究者がRなどでループを書き、意味解釈が必要な部分だけLLMに応答させる）。APIは「プログラムをデータのように使える」革命で、70〜80年分のプログラム蓄積を活かせる。
  • 得意: 構造化データ生成・非構造データの意味読み取り・自由記述の分類。1400年以降の絵画63万点から感情を抽出する実験では ChatGPT が8枚中7枚正解。GPUで2時間以上かかる処理が8分で完了する例も。ただし問い・判断・執筆は研究者の手元に残す。
  • 苦手: ハルシネーション、文献検索、歴史的事実・データ参照、空間推論、因果推論の設計、回帰モデルの変数選択、ノイズの多い代理変数。AIに考えさせすぎると自分の判断力が低下する点も（バークレー校のAI全面禁止の例、AIに論文を書かせる指導への批判とあわせて）。

9.2 ループ・エンジニアリング演習 — 参加者の実践

  • 繰り返し作業をLLMとのループとして設計し、小さく回して検証しながら改良する考え方（Andrew Ng）。事前資料の Lynch／Ng 記事をベースに、各自の「繰り返し直していること・指示していること」を持ち寄って討議。
  • 論文処理ループ（鈴木 康太）: 論文PDFを ①Markdownに変換 → ②フォルダ格納 → ③リネーム → ④日本語要約生成、の一連をワンコマンド化。PDFのままではAIが読み違えるためテキスト化が肝で、Vision系ライブラリを併用すると精度が上がる。「新卒1〜3年目に渡していた作業がこのループで回る」との実感。
  • 財務モデル（宮武）: 結論が確定している計算は任せられるが、PLへの組み込みやキャッシュフローへの織り込みなどクリエイティブな判断を任せると破綻する。エージェントに作業させたあと別の専門家にレビューさせる「外部フィードバックループ」が有効。
  • 修論研究の実践例: エージェンティックなら理解度5%でもトップジャーナル級のモデルが実装できてしまう。Claude → Codex でクロスチェック → さらにレビュー、と走らせると自分の関与が薄いまま完成し「どこへ向かったのか分からない」状態に陥る、という反省。
  • 限界: 最大公約数的な内容は対応できるが、全く新しい概念を提示する論文にはLLMが追従できない。結局、英語原文は自分で読む必要がある。
  • 判断基準は「検証コストの安さ」: LLMが何を得意とするかではなく、自分の業務で最も安く検証できるものからループ化すると確実に効果が出る。

9.3 リアルオプションと「学習」という新しい不確実性

  • 川口先生は来月のリアルオプション学会での講演を準備中。リアルオプションの3要素は不可逆性・不確実性・柔軟性（待つことの価値）。不確実性は ①市場 ②ゲーム的（相手の行動）③技術的（成否）の3種。
  • 新しい知見は技術的不確実性と「学習」の結びつき。従来の「やってみないと分からない」から、いまは「やってみても分からない」——LLMが答えを返すが、それが正しいか検証できない——という新しい不確実性が登場した。
  • 学習・問いの作り方・知識への投資が新しい投資概念のキーワードであり、リアルオプション・VC・イノベーションを統合する枠組みになりうる。「問いは作れない（問いを考えることこそ人間の仕事）」という強調も。

9.4 AIの経済的影響（宮武さんの論点提起）

  • AI活用は ①既存業務の効率化 と ②新しい需要・供給の創出 に分けられるが、現状は効率化中心でゼロサムに留まるのではないかという問題提起（事前にClaudeと論点整理したファイルを共有）。
  • ゼロサムを超える経路: 供給コスト低下による実質所得増、ジェボンズのパラドックス（安くなれば需要増）、専門サービスの民主化（医療・法務）、無料AIによる非市場的な消費者余剰。
  • 効率化は株主に有利で被雇用者に不利になりうるという論点。日本ではバックオフィス効率化が中心で、フロント活用は製造業のAX（AIトランスフォーメーション）の一部に限られる。不動産のフロントでAIが効きにくいのはIoT（センサー）の遅れが一因。
  • ITバブルとの違い: 当時はソフトウェア完結型だったが、今回はデータセンター等の物理投資（ハイパースケーラー、民間の規模を超えた投資）が発生。無形資産＝知識への投資という新フロンティアで、投資という概念自体が変わりつつある。
  • ソフトウェアの民主化: ある不動産会社では文系のバックオフィス担当が自然言語でPCを操作して画期的成果を上げた例も。教育なしでプログラムを扱えるようになった革命こそ本質、という指摘。

9.5 セキュリティリスク

  • エージェンティックAIはライブラリ等を自動インストールするためリスクが高く、大企業・金融機関の業務端末では特に注意。Claude Code 利用者が顧客データを含む環境を誤ってGitHubに公開してしまった実例も共有された。
  • 対策: サンドボックス（仮想環境）にパーミッションを限定、社内データ専用のクローズド環境と外部アクセス環境の分離。金融機関では限定環境のみ利用というケースも。「セキュリティオフィサーの判断が正しいか自分では検証できない」という構造的な悩みも。
  • 失敗例: Google Meet の録画が10分で切れる問題は、LLMに聞いても解決せず実は設定1つだった——UIが頻繁に変わる領域ではLLMの知識が古く、「本日時点のドキュメントを読んでから回答」等のプロンプトが有効。

9.6 昼食懇談（抜粋）

  • ITバブルとAIブームの比較: インターネットは「距離の消滅」という新しい体験を生んだが、AIで同種の新産業がまだ見えない、という違和感の提起。一方で、鉄道会社モデル（インフラ＋不動産＋オペレーション）とデータセンターの類似性、テナントリスクの大きさの違いも議論。10月シンポジウムのキークエスチョン候補に。
  • AIと社会構造: 少数への富の集中とベーシックインカム論、AWS・Anthropic等（ひいては米国）への資金集中で日本が果実を受け取れないリスク。楽観論としては、コスト削減が生産量増につながれば全体のウェルフェアは向上しうる、ブルーカラーの賃金上昇も進んでいる、という整理。むしろ新入社員のトレーニング機会の喪失の方が深刻という指摘も。
  • 投資概念の拡張: 川口先生が最近のNBER論文（投資・リアルオプションの拡張に関わるもの）に「30年前にリアルオプションと出会った時と同じインパクト」と注目。来月のリアルオプション学会講演の柱に据える意向で、詳細は学会後にゼミへ共有予定。LLM連続講義が一区切りしたあとの、ゼミの次の独自テーマ候補。
  • ガバナンス談義: 社外取締役は月1回の取締役会資料だけでは内情把握に限界がある、D&O保険の上限と巨額訴訟リスク、循環取引等の組織的不正は外部から発見困難で最終的に内部告発に頼らざるを得ない、といった実務の難しさ。
  • 市場環境: 日銀の利上げトレンド下でも実質金利はなおマイナスという見方、円安の進行と外貨資産課税の話題、「不動産は悪い時に買い、良い時に我慢する」の鉄則と人口減下のリカバリー懸念。
  • ほかに、孫正義氏の半自伝（フィナンシャルインベスターとしての評価）、シリコンバレーのエコシステム、宇宙開発、日本のポップカルチャーの強み、WBS卒業生の起業家など幅広い話題。
