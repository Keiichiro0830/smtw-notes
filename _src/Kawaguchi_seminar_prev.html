第4回（7/18）事前資料

当日は「ループ・エンジニアリング演習」を中心に、テーマ「企業におけるAI活用」を議論します。冒頭のカードは川口先生の当日プレゼンスライド（7/18朝 Ver2に差し替え）。続く2カード（演習の事前読み物・テーマ資料）が今回の新しい問題提起、そのあとに日経記事課題、後半は第3回までの議論を受けた「理論×実例」の教材です。各カードから資料ごとのコメントも送れます。

当日プレゼン資料 ／ 川口先生 7/17共有 → 7/18朝 Ver2に差し替え
川口 有一郎 — LLM・生成AI活用ガイド ― 研究・実務：ループエンジニアリング（Ver2）

第4回当日に先生が使用されるスライド（全24枚）。過去4・5・6月の「LLMとは何か？その活用方法は？」の検討を踏まえた「とりあえずの総括」です。前半は Ferrara（ピッツバーグ大）の NBER 論文（WP 35374・経済史研究における LLM・生成AI 活用の実践ガイド）を下敷きに、LLMの限界とリスク、反復的な対話ワークフロー、実例（新聞記事の構造化、絵画63万枚の分類ほか）を整理。中盤がループ・エンジニアリング演習パート（事前読み物 Lynch／Ng の各1枚要約、「自分のループ」の設計手順、当日までに考えておく2つの問い）、終盤に「LLM as system connector」の問題提起と「検証コストの安さ」基準・「硬い骨格、柔らかい末端」の設計原則が続きます。7/18朝の Ver2 では、事前読み物のページが Lynch（p.17）と Ng（p.18）の2枚に拡充されました。

ループ・エンジニアリング演習 — 事前参考資料（Lynch & Ng）

当日は、参加者それぞれの興味とAIスキルのレベルに応じた「自分のループ」を設計してみる演習を予定しています。事前の参考資料は2つ。1つはLynch氏（プレシードVCの創業パートナー）の「Claude Codeをチーフ・オブ・スタッフとして使う10の方法」（川口先生の和訳付き）——メール・CRM・ドキュメントをまたぐ自分の業務をAIのループに載せた実例集です。もう1つはStanford Andrew Ng氏のThe Batch記事。ご自身の仕事の中で「繰り返し直していること・繰り返し指示していること」を1つ2つ思い浮かべながら読んでいただくと、当日そのまま演習に入れます。

川口 有一郎 — LLMの活用方法（一例）: LLM as system connector, not thinking brain

先生の問題提起：現在、実務（特にバックオフィス）で起きている革命は「API → LLM → ソフトウェアの民主化」。Gemini の表現を借りれば、LLM は「考える脳」ではなく「システムを繋ぐ柔軟な接着剤」（例：Salesforce の Agentforce Operations）。一方で「LLMの仕組みから考えると、不動産業では人間にとって代わるような業務は少ないのでは？」という問いも（不動産業に限定せず議論します）。添付は同じ問いを Claude に投げた出力で、「モデルの賢さではなく、出力の検証コストの安さが活用の成否を決める」という単一基準から、良い活用の四条件、「硬い骨格、柔らかい末端」の設計原則までを整理したものです。
