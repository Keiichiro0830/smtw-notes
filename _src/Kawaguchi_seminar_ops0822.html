3. プログラム（中身）

川口先生の設計（8/1 メール）— 「エージェンティック時空統計学入門チュートリアル」

8月1日に先生から当日の設計をご共有いただきました。位置づけは、LLM三部作を「理解するための基礎」としての時空統計学（依存性の統計学）「入門」です。柱は3つです。

① 2025年演習の「ポイントの復習」

2025年の演習を受講していない参加者がいるため、ここを一つの柱に据えます。

② Claude Code を用いたエージェンティック（新規）

「統計モデリングのループ」は、AIチャットを活用して人間が「考える」ループと、Claude Code に「自律的に処理させる」ループから成る、という理解です。これを各自のPC上で実装します。

③ 人間は「判断」、機械が「実行」

先生は7月31日に、2025年演習オリエンテーション時の回帰分析で①②を実際に試されています。そこで分かったこととして、いろいろな統計モデルの「本質を知らない人は不要」となる一方、その本質を知っている人はR言語やプログラミングなどの技法や経験はほとんどいらない、と整理されています。人間は「判断」に集中し、機械が「実行」を担当する、という建て付けです。

2025年演習と大きく異なるのは②で、その結果「あなたがRでコードを書く必要はほとんどないです」。その代わりに、参加者それぞれのPCを RStudio が動き、かつ Claude Code が動く環境にしていただく必要があります。先生は参加者の環境を同一レベルにする準備に約1時間を当てるイメージを示されています。環境さえ整えばRコードを一から書く必要も、R言語を知る必要もほとんどありませんが、実際にはいろいろと「壁」にぶつかるため、松前・宮武さんなどのアドバイスが必要になる（先生ご自身もそうである）とのことです。

先生のお言葉では、中途半端に知っている人が不要になる時代がやってきたことを、統計モデリングを材料に体験する機会であり、そこで「本質」に集中する結果として、LLM三部作を理解するための「ヒント」が得られるだろう、という見通しです。そしてこれを基礎として、10月のシンポジウムでは「投資の新しい概念」を議論することになる、と10/3への接続も示されています。（メール「Re: 8/22 研究会（合宿）および10/3の秋のシンポジウムにつき、お打合せ依頼」8/1 00:32。「5日に具体的にお話できると思います」とのことですので、8/5の打合せで詰めます）

【8/5で解決】参加者のPC環境は「R と RStudio だけ」になりました。8/3版では、参加者全員に Claude Code の環境を用意していただく前提で、アカウントと課金をどうするかを最優先の論点としていました。8/5の打合せで先生より「Claude Code を契約していなくてもいいんですね。R だけあれば、R のところは自分でやればいいので」とご整理いただき、この論点は消えました。参加者にお願いするのはR と RStudio のプレインストールだけで、AIツールはお使い慣れたもので構いません。Claude Code は松前・宮武さん・先生が使う側として実演する位置づけです。
→ これに伴い、当日冒頭の「約1時間の環境合わせ」も不要になりました。10:00から本編に入れます。なお、Claude Code を入れてみたい方向けのインストール手順は、別途ご案内する方向で先生と一致しています（必須ではありません）。

事前課題（8/5 川口先生よりご提示）

当日は「聞いているだけでは身につかない」ため、先生から事前課題が出ました。村上さんの教科書に対応するデータリスト（先生より配布済み）から各自1つデータを選び、次の順で進めます。

step内容誰が事前に／当日に
1データリストから1つ選ぶ2025年演習の受講者は経験済み／未受講の方は当日はじめて体験
2そのデータの背後にある構造を探す
3単一のモデルでなく複数のモデルを試行錯誤する
4その試行錯誤の部分をAIのループに載せて試す（新規）受講者はここまでを事前に
5やってみた感想を持ち寄って紹介する当日

2025年演習との違いは4番だけです。先生の言葉では、2025年は「村上さんのテキストの各章のモデルを理解する」演習でしたが、今回は「このデータに最もフィットするモデルは、テキストのどのモデルか」を探しに行く——つまりデータの背後にある構造の探索がテーマです。事前知識としては ARIMA とニューラルネットワークモデルの知識があるとよく、先生は OTexts を挙げられました（機械翻訳で読める、とのこと）。

当日の流れ

  1. 松前・宮武さんから、Claude Code を実際に使った経験を報告（鈴木 康太さんはご欠席のため、事前に試した結果をメール等で共有）
  2. 川口先生がスライドで「私はどうやったか」を紹介し、はじめての方もここでジョイントできるようにする
  3. 午後は各自で手を動かす

先生の設計意図は「ゴールを先に見せる」ことです。「去年受けた人がAIのループを組み込んだ経験を先に紹介すれば、佐々木さんや飯沼さんにとってはゴールが明確になるので、そこから逆算して戻ってこられる」——2025年演習の受講者と未受講者でワークストリームが分かれてしまう問題への、先生の解き方です。

8/5 のデモで分かったこと（Boston 住宅データ）

打合せの中で先生が画面を共有され、Boston 住宅データの OLS と WLS を Claude Code に実行させたデモをご覧いただきました。運営として押さえておくべき点は3つです。

RStudio は起動しなくてよい

Claude Code が R を直接呼び出して結果を返すため、R 本体は必要だが RStudio を開く必要はない、というのが先生の実際の運用です。先生ご自身「私は松前さんの話を聞いて驚いた。RStudio から Claude を使うやり方もあるけれど、私の場合は Claude の言う通りにやったら RStudio を使わなかった、単に置いてあるだけだった」。

人間の役割は「設計」に寄る

モデル選択・残差の解釈・次にどのモデルへ進むかの判断は人間が行い、コードの実行は Claude Code に委ねる。先生の資料では左が人間、右が Claude Code、という分担で整理されています。

AIの限界がテーマになる

松前より「残差をどう見るかをこちら側から指定しないとうまくいかない。GLM がいいか INLA がいいかまで言い当てるほど気は利かないだろう」、鈴木 康太さんより「線形回帰の残差を読んで、空間構造を入れるか時間構造を入れるかまで判断できるかが興味」。先生も「的確な答えを出すかどうか分からないし、嘘かもしれない。それはやってみて議論しましょう」。どこまでできてどこから human が要るのか、その境目を見つけること自体が当日の成果物という位置づけです。

なお先生からは、英語圏の統計教育で「バイブ統計モデリング（vibe statistical modeling）」が論点になっており、汎用AI（Claude / Gemini / ChatGPT）と統計特化AIの比較研究が進んでいる、というご紹介もありました。当日ご紹介いただく予定です。

先生から、議事録を書籍の草案にするというご構想が出ました。「経験が深い人だけではダメで、はじめて Claude Code をやるという人の意見も必要。いろんな人の情報共有をした議事録が、多分テキストの草案になる」。当日の自動議事録は、記録ではなく成果物として扱うということですので、松前側で録音・文字起こしの体制を確実にしておきます。鈴木 康太さん・諏訪部さんはご欠席のため、この議事録を読んでコメントをいただく形にします。
